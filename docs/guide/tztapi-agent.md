# 中焯行情接口开发指南（tztapi-agent）

适用于在 GXQuotes 中**新建行情接口、核对参数、修正响应解析**。Codex 或其他代码 Agent 只需当前仓库即可开始；已配置独立 `tztapi-agent` 时，可让它协助查证或验证，不是依赖。只需要调用现有方法查行情时，读 [gxquotes Skill](../../skill/SKILL.md)。

## 从需求到交付

1. **先查是否已有接口。** 看[接口功能清单](../API/接口功能清单.md)，定位最接近的 Fetcher 和测试。现有方法能满足需求就复用；只有缺少能力才扩展 Python 包。仅在需求确实需要直接通过 Skill 调用时，才同步增加或更新 CLI。
2. **用官方文档确定契约。** 从[中焯官方文档索引](../API/中焯官方文档/README.md)按问题选文档：总览确定 Action，业务接口文档确认请求参数和响应形状，属性 ID 表确认字段、类型、单位，市场资料确认市场编号与范围。记录文档名和章节，整理必选/可选参数、默认值、分页/时间范围、返回字段及空结果和错误语义。资料缺项、与已有实现或实测冲突时明示，不猜字段，也不把一个 Action 的规则套到另一接口。
3. **先写最小请求，再封装。** 沿用 `KLineFetcher` 及现有 Fetcher 结构，通过现有 `TZTClient` 调用只读 GET，继承会话、限流、重试和错误分类，不直接发 HTTP。有权限时用一个标的或一小页验证响应，再扩大范围。市场解析复用 `tzt_api/market.py`；普通行情字段复用 `quote_fields.py`，但仅采用此 Action 文档支持的字段和单位。保留现有错误语义：不要把网关失败变成正常空结果；默认兼容行为和 `strict=True` 的异常行为分别验证。不要把网关地址、凭证或未脱敏响应写进示例、日志、测试或提交。
4. **分开验证离线与在线。** 在仓库独立虚拟环境中运行 `python -m pytest -q -m "not integration"`。新增 mock 测试至少覆盖最小请求、正常解析和单位、空结果、异常；若涉及分页、市场歧义或时间边界，补相应测试。仅当当前环境已有授权行情配置时，再用 `python -m pytest -q -m integration <相关测试文件>` 做小范围实测。没有配置或连不通时，仍可交付封装和离线结果，明确标为「未实测」，不要用历史记录或 mock 结果代替本次实测。
5. **更新公开契约与证据。** 在[接口功能清单](../API/接口功能清单.md)记录方法、参数、单位、已知限制和验证状态。新增公共类时检查 [包导出](../../tzt_api/__init__.py)；有 CLI 变化才更新 [quotes.py](../../skill/scripts/quotes.py)、[Skill 文档](../../skill/SKILL.md)和 CLI 测试。用户可见的行为变化写入 [CHANGELOG](../../CHANGELOG.md)。交付时列出文档出处、文件、离线/在线结果及仍未验证的行为。结论可标「实测确认」「文档确认」「文档存疑」「未验证」。

从 [10006 接口文档](../API/market_rank_api.md)看请求与响应映射，再读 [MarketRankFetcher](../../tzt_api/market_rank.py) 对照证券池、排序、字段换算及稳定返回结构。这个例子还说明：实时排行跨页不是同一时刻的全市场快照，不应把分页数据当作一次同步截面。

## 可直接交给 Agent 的任务示例

> 在 GXQuotes 中新增中焯成交明细（Action 10003）的 Python 封装。先查接口清单，再从仓库内官方文档确认参数、返回字段和单位；沿用现有传输层与市场解析。先交付库函数和 mock 测试，不加 CLI。已有授权环境才做单标的小范围实测；否则报告哪些行为未实测。给出文档出处、测试命令和结果。

## 可选：使用独立 tztapi-agent

ZCode 已安装时可用 `/tztapi-agent <需求>`；Claude Code 已配置时可点名该子智能体。独立项目是[私有仓库](https://github.com/seuzxh/tztapi-agent)，有权限时可查其 [USAGE.md](https://github.com/seuzxh/tztapi-agent/blob/main/USAGE.md)。没有权限、没有安装或没有子智能体能力时，直接走上面的仓库内流程。
