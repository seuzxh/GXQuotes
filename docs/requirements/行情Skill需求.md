## 1. 背景与定位

GXQuotes（Python 包名 `tzt-api`）目前是一个面向开发者的中焯行情 API 客户端库（4 个 Fetcher、13 个公开方法 + 共享传输层，详见[接口功能清单](../API/接口功能清单.md)）。

**项目目标**：在库能力之上封装一个**行情 Skill**——让智能体（agent）能以自然语言意图直接获取 A 股行情数据，无需了解底层 HTTP 接口、市场代码推断、字段单位换算等细节。

边界划分：

| 层 | 职责 | 载体 |
|----|------|------|
| **行情 Skill**（本项目标） | 意图 → 数据的封装：参数校验、标的解析、错误自诊断、结果口径统一 | Skill 定义（SKILL.md + 脚本入口） |
| tzt-api 库（现有，v1.1.0） | HTTP 客户端：进程级限流、重试、解析、单位换算、类型化异常 | `tzt_api` 包 |
| tztapi-agent（现有子智能体） | 中焯接口层的专家：新建/校验底层接口 | `~/.zcode/skills/tztapi-agent` |
| kline-qlib（兄弟仓库） | qlib 数据管道（批量下载 + bin 转换） | kline-fetcher 仓库 |

## 2. 使用场景（User Stories）

- 作为**量化研究员**，我想问「茅台近 3 年后复权日K」，直接得到带复权因子的标准 K 线数据，以便做回测
- 作为**策略开发者**，我想取「沪深300 指数 5 分钟K」，无需记忆指数代码与市场归属
- 作为**盘面分析师**，我想查「某股今天集合竞价与盘中分时」和「上周五的历史分时」，用于盘中行为分析
- 作为**题材跟踪者**，我想知道「这只股属于哪些概念板块」「某板块有哪些成份股、板块指数走势如何」

## 3. 功能需求（FR）

### FR1 K 线行情（日K / 分钟K）
- **周期**：日K；分钟K 1/5/15/30/60min
- **复权**：前复权（qfq）/ 后复权（hfq）/ 不复权（none）三种口径；个股场景提供**复权因子**（factor），成交量可还原为真实股数
- **取数方式**：按数量（最近 N 根）或按日期区间（begindate/enddate）
- **返回字段**：`date[/time] / open / high / low / close / volume / amount[/factor]`，单位统一为元、股
- 验收：三种复权口径单测覆盖；复权因子与公开基准（东财/新浪）抽样一致

### FR2 分时行情（实时 + 历史）
- **当日实时分时**：截至调用时点的盘中序列（3 秒粒度），含盘前集合竞价段（参考价、已配对量、未配对买卖量）与盘中段（最新价、均价、量、额）
- **历史分时**：指定交易日（YYYYMMDD）的同结构数据
- 口径说明：分时为原始成交序列，**无复权概念**（历史分时价格为当日实际价，除权日前后存在自然跳变）
- 验收：个股与指数均可取；两段数据（pre_market/trading）结构稳定

### FR3 标的覆盖：个股 + 主要权重指数
- **个股**：沪（600/601/603/605/688/689）、深（000/001/002/003/300/301）、北（8/4/920）全号段
- **指数白名单**（26 个，`INDEX_CODE_MAP`）：上证50、沪深300、中证500/800/1000/100、科创50/100、创业板指/综/50、深证成指、北证50 等，覆盖需求列举的全部指数
- **解析规则**：显式前缀（sh/sz/bj）> 指数优先 > 号段推断；**歧义必须可解**（裸码 000001 = 上证指数，深市平安银行需 sz000001——skill 层需向用户澄清或默认按指数并提示）
- 验收：白名单全量指数参数化集成测试通过（现有 102 项集成测试已含）

### FR4 概念板块归属与成份
- **个股 → 板块**：返回个股所属全部板块，类型标注（industry 行业 / region 地域 / concept 概念风格），支持按类型过滤
- **板块 → 成份股**：指定板块代码返回成份股清单（代码/名称/市场，含最新价/涨跌幅）；全量场景用生成器自动翻页（剔除板块自身）
- **板块发现**：获取全部概念板块列表（名称 ↔ 代码映射，实测约 390 个）
- 验收：600519 等样本股的板块归属与东方财富公开口径抽样一致

### FR5 板块/概念指数行情
- 板块指数日K（价格/量/额，单位已换算为元/点/%），支撑「板块走势如何」类问题
- 板块行情快照字段（最新价、涨跌幅）口径可用（v1.1.0 起已换算）

### FR6 Skill 交付形态（本项目的核心增量）
- 以 **Skill 定义**交付（SKILL.md + 基于本包的可执行脚本/代码片段），可被 Claude Code / ZCode 等 agent 运行时加载
- **意图 → 接口路由**：自然语言参数（代码/名称/周期/复权/日期）映射到 FR1–FR5 的库方法
- **错误自诊断**：失败时返回结构化、可行动的错误信息（区分：标的不存在 / 无数据 / 网关不可达 / 参数非法）——库层 v1.1.0 已提供 strict 模式类型化异常与 last_error，skill 层负责转译为人/agent 可读信息
- **安全铁律**（继承 tztapi-agent 约定）：只读 GET、限流 ≥0.1s（库层 v1.1.0 已进程级共享）、API 地址走环境变量不入库
- 验收：一个此前不了解本项目的 agent，仅凭 SKILL.md 完成 2. 节全部四类场景

## 4. 非功能需求（NFR）

| # | 需求 | 说明 |
|---|------|------|
| N1 | 数据口径 | 全接口价格/成交额=元、成交量=股、比率=%（v1.1.0 起含板块快照字段，已统一） |
| N2 | 可靠性 | **进程级共享限流 0.1s（✅ v1.1.0）**、失败重试指数退避；待办：不可重试 ErrorNo 分类（如 -2300 代码错误不应重试 3 次 + 退避 7s） |
| N3 | 失败语义 | 库层默认 None 兼容；**strict 类型化异常 + last_error 已具备（✅ v1.1.0）**；skill 层错误转译待 M2 |
| N4 | 依赖约束 | 零 numpy；仅 requests + PyYAML；Python ≥3.9（沿用库现状） |
| N5 | 可测试性 | 双层测试（mock 单测 + 真实网关集成测试），新能力同规则 |
| N6 | 兼容性 | 库公共 API 严格向后兼容（kline-qlib 依赖） |
